**Problem:** Test used `Modules\Sales\Models\Customer` but Payment model uses `Modules\Contacts\Models\Contact`

### 2. Payment Number Auto-generation Missing

**Problem:** `payment_number` field is UNIQUE NOT NULL but not autogenerated

**Analysis:**
- Migration: `payment_number` → string, unique, NOT NULL
- PaymentRequest: `paymentNumber` → nullable (INCORRECT for new records)
- No auto-generation service like ARInvoice/APInvoice

**Temporary Fix:**
- Test manually generates: `'paymentNumber' => 'PAY-' . time()`

**Required for Phase 2:**
- Implement PaymentService with auto-generation:
  ```php
  class PaymentService {
      private function generatePaymentNumber(): string {
          $last = Payment::orderBy('id', 'desc')->first();
          $next = $last ? ((int) substr($last->payment_number, 4)) + 1 : 1;
          return 'PAY-' . str_pad($next, 6, '0', STR_PAD_LEFT);
      }
  }
  ```

## Validation Issues (Non-Critical)

### All Finance Requests have nullable fields

**Issue:** PaymentRequest, BankAccountRequest, etc. have ALL fields as `'nullable'`

**Impact:**
- Database constraints (NOT NULL) catch errors → 500 errors instead of 422 validation
- Should be `'required'` for NOT NULL database fields

**Example:**
```php
// CURRENT (PaymentRequest.php):
'customerId' => ['nullable', 'integer'],  // DB is NOT NULL
'amount' => ['nullable', 'numeric'],       // DB is NOT NULL

// SHOULD BE:
'customerId' => ['required', 'integer'],
'amount' => ['required', 'numeric'],
```

**Fix Priority:** Phase 2 regeneration will fix this
